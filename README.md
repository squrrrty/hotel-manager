# HotelManager

Небольшая система ресепшена: номера, гости, брони, заезд и выезд.
Стек сохранён: Flask, Flask-Login, SQLAlchemy, Flask-Migrate, PostgreSQL,
Jinja2, Bootstrap 5, обычный JavaScript. Для хостинга предусмотрен отдельный Gunicorn-сервер.

## Запуск на Windows

Нужны Python и работающий PostgreSQL 18. Проект проверен на Python 3.13.17.
В исходном паспорте указан Python 3.14+, он в этой среде не проверялся.
В PowerShell откройте папку проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Создайте пустую базу `hotel_manager` в PostgreSQL через pgAdmin или `createdb`.
Скопируйте `.env.example` в `.env`, если конфигурации ещё нет. Укажите свой
пароль PostgreSQL и секретный ключ. Существующий `.env` не перезаписывайте.
Затем:

```powershell
.\.venv\Scripts\python.exe -m flask --app run db upgrade
.\.venv\Scripts\python.exe seed.py
.\.venv\Scripts\python.exe run.py
```

Откройте http://127.0.0.1:5000. Демо-вход: `admin` / `admin123`.
Bootstrap подключается через CDN, для загрузки его стилей нужен интернет.
В архиве нет `.venv`, `.env`, базы данных и истории Git.
Для повторения именно проверенного окружения можно вместо `requirements.txt`
установить `requirements-lock.txt` — библиотеки те же, закреплены их версии.

## Что добавлено

1. В разделе «Номера» выберите даты и нажмите «Подобрать номера».
   Отобразятся номера без пересечений с активными бронями, кроме ремонта.
   Кнопка «Забронировать» переносит номер и даты в форму заявки.
2. При выборе номера и дат форма считает ночи и ориентировочную стоимость.
   В списке броней показан такой же расчёт на сервере.
   Это текущий тариф категории × число ночей, без услуг и учёта оплат.
   Сумма не фиксируется в БД: при изменении тарифа оценка тоже изменится.
3. После выезда номер уходит на уборку. В списке номеров кнопка
   «Уборка завершена» возвращает ему статус «Свободен».
4. Поиск гостей по имени, телефону и email; фильтр броней по статусу.
5. На главном экране — загрузка, последние брони, ожидаемые заезды и выезды.

Фильтр дат проверяет будущие брони, а текущий статус — готовность сейчас.
Поэтому занятый сегодня номер может быть доступен для будущего периода.
Заселение разрешено только в даты проживания и только в готовый свободный номер.
Занятость меняется через брони, отмена уже заселённой брони запрещена.

## Проверки

Используется pytest из исходного requirements.txt. Создайте отдельную тестовую
БД PostgreSQL, например `hotel_manager_test`, и выполните:

```powershell
$env:TEST_DATABASE_URL='postgresql+psycopg2://postgres:your_password@127.0.0.1:5432/hotel_manager_test'
.\.venv\Scripts\python.exe -m pytest -q
```

Каждый тест создаёт и удаляет собственную временную схему `test_<uuid>`.
Пользователю БД нужны права на создание схем. Без TEST_DATABASE_URL тесты
пропускаются. Не путайте пропуск с успешной проверкой.

Результаты и ручные сценарии: `TEST_REPORT.md`.
Объяснение кода для защиты: `CODE_GUIDE.md`.
Исходный паспорт: `project_notes.md`.
